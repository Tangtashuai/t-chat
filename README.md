# t-chat1.3 聊天室

> **制作：汤at帅**
> B站主页：<https://space.bilibili.com/3546392266017069?spm_id_from=333.1007.0.0>

t-chat1.3 是一个自建、局域网/公网都能用的即时聊天应用：注册登录、公共聊天室、私聊、群聊、任意文件上传下载、好友系统、封禁系统、黑白主题、聊天背景、管理后台，以及 8 关 PICO PARK 风格联机合作小游戏。

后端只使用 **Python + Flask + Flask-SocketIO + SQLite**，前端是原生 HTML/CSS/JavaScript。**不需要 Node.js，不需要数据库服务，不依赖外网 CDN**（Socket.IO 客户端已经放在本地 `static/socket.io.min.js`）。

## 二、数据目录（1.3 重点）

首次启动后会自动生成：

```text
t-chat1.3/
├─ data/
│  ├─ users/
│  │  ├─ users.db          # 用户、好友、群聊、设置、封禁、违禁词、申请
│  │  ├─ avatars/          # 头像
│  │  └─ backgrounds/      # 聊天背景
│  ├─ messages/
│  │  └─ messages.db       # 所有聊天消息（含发送者快照）
│  └─ files/
│     ├─ ...               # 用户上传的任意格式文件
│     └─ tutorial/         # 管理员上传的教程视频
├─ static/
├─ templates/
├─ server.py
├─ start_tchat.py
├─ run.bat / run.sh
└─ README.md / TUTORIAL.md
```

- 备份：直接复制整个 `data/` 文件夹。
- 替换用户数据：替换 `data/users/users.db`（建议停服操作）。
- 删除聊天记录：删除/替换 `data/messages/messages.db`。
- 删除文件：直接清理 `data/files/`（数据库里的消息链接会失效）。
- 不要把 `data/` 提交到公开仓库，里面包含密码哈希和聊天内容。

### 从 1.2 迁移

1. 先备份 1.2 的 `chatroom.db` 和 `uploads/`。
2. 把 `chatroom.db` 和 `uploads/` 复制到 1.3 的 `data/` 目录（也可以放在 1.3 根目录）。
3. 启动 1.3。程序会自动把旧用户、好友、群聊、消息、文件导入三个新文件夹，旧库不会删除。
4. 迁移完成后建议保留旧库备份，确认无误后再清理。

> 建议在第一次启动 1.3 之前复制旧数据；只要旧库还在 `data/` 或程序根目录，启动时会尝试导入。

## 三、Windows 快速开始

### 方式 A：一键启动脚本（推荐）

双击 `run.bat`。脚本会：

1. 自动寻找 Python 3.6~3.13；
2. 优先使用系统已安装的兼容依赖，否则创建 `.venv` 并安装；
3. 根据 Python 版本自动选择 `requirements.txt` / `requirements-legacy.txt` / `requirements-py36.txt`；
4. 启动服务。

启动后打开：

- 聊天室：<http://127.0.0.1:5000>
- 管理后台：<http://127.0.0.1:5000/admin>

### 方式 B：自动程序

```bat
python start_tchat.py
```

它会检查依赖、启动服务、等待端口就绪并自动打开浏览器；按 `Ctrl+C` 停止。

### 方式 C：手动

```bat
python -m pip install -r requirements.txt
python server.py
```

如果 Python 是 3.6/3.7，请使用 `requirements-py36.txt` / `requirements-legacy.txt`。

### 首次登录管理员

- 地址：`/admin`
- 默认密码：`abc12345`
- 登录后请立刻在“修改管理员密码”里改掉。
- 忘记密码：停止服务，设置环境变量 `ADMIN_PASSWORD=新密码` 和 `TCHAT_ADMIN_FORCE=1` 后启动一次，即可强制重置。

## 四、Linux / macOS

```bash
cd t-chat1.3
chmod +x run.sh
./run.sh
```

或手动：

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python server.py
```

默认监听 `0.0.0.0:5000`。公网部署请用 Nginx/Caddy 反向代理，并加上 HTTPS；不要直接把 Flask 开发服务器长期暴露在公网。

### 环境变量

| 变量 | 默认 | 作用 |
|------|------|------|
| `HOST` | `0.0.0.0` | 监听地址 |
| `PORT` | `5000` | 端口 |
| `TCHAT_DATA_DIR` | `程序目录/data` | 数据根目录（可放到别的盘） |
| `ADMIN_PASSWORD` | `abc12345` | 首次初始化管理员密码 |
| `TCHAT_ADMIN_FORCE` | 空 | 设为 `1` 时用 `ADMIN_PASSWORD` 强制重置 |
| `TCHAT_DB` | 空 | 指定旧版 `chatroom.db` 路径（一般不用） |
| `SECRET_KEY` | 自动生成 | Flask session 密钥 |

## 五、使用说明

### 注册 / 登录

- 新账号注册成功会自动登录并进入教程页。
- 教程页可以看管理员上传的视频，也可以直接“进入聊天室”。
- 只有首次注册会强制进入教程；以后可在设置里点“使用教程”。

### 好友

- 左侧「添加好友」：搜索用户名，发送申请。
- 左侧「好友申请」：查看收到/发出的申请，同意、拒绝或撤回；支持搜索。
- 好友列表按管理员设置的间隔自动刷新（默认 10 秒）。

### 群聊

- 建群至少需要 3 个人（含自己）。
- 群主在群聊右上角「更多」里可以：查看群成员、踢人、邀请好友、审批入群申请。
- 普通成员也可以邀请好友，但必须由群主在「入群申请」里同意。
- 公共聊天室没有「更多」菜单。

### 文件

- 支持任意扩展名；图片/视频/音频直接预览，其他文件显示下载卡片。
- 单文件默认上限 500MB（`MAX_UPLOAD_MB`）。
- 文件保存在 `data/files/`，消息里保存文件名、大小、扩展名和 URL。

### 聊天背景

设置 → 聊天背景 → 选择图片。支持 png/jpg/gif/bmp/webp，最大 16MB。只影响自己的聊天界面。

### 公共聊天室规则

- 每人每 5 秒只能发一条；客户端会提示剩余秒数，服务器也会强制拦截。
- 管理员添加的违禁词只在公共聊天室检测；命中会拒绝发送并提示具体词。

### 封禁

- 管理员在后台用户列表点“封禁”，可同时封禁该用户最近 IP。
- 被封禁用户登录会失败；已登录用户访问页面会跳转 `/banned`；接口返回 403。
- 被封禁用户的名字后面显示“（已封禁）”；解封后标签自动消失。
- 管理员账号不能被封禁；服务器本机 IP 不能被 IP 封禁。

### 多开 / IP 限制

- 默认每个 IP 最多 2 个账号。
- 服务器本机 `127.0.0.1`/`::1` 不受限；后台「创建小号」也不受限。
- 达到上限时登录页会出现“申请多开”；管理员批准后自动创建账号，并为该 IP 增加 1 个名额。
- 管理员可以给单个 IP 设置专用上限。

### 小游戏

- 左下角「加入/创建小游戏」，输入 4 位房间号。
- 勾选“私人房间”后，只有收到邀请的人能加入。
- 房间内点「分享游戏给好友 / 群聊」，会发送一张邀请卡片；好友点“加入游戏”自动带房间号打开。
- 房主可以开始游戏、在等待厅把玩家“移出”；被踢的人不能重新加入该房间。
- 8 关，所有玩家收集全部钥匙并一起站进终点门才能过关；可以踩队友的头。
- 管理员关闭小游戏后，聊天室隐藏入口，游戏页重定向，接口返回 403。

## 八、常见问题

**Q：页面一直“连接已断开”？**
A：确认 `python server.py` 还在运行；公网部署要允许 WebSocket/长轮询，并检查反向代理的 `Upgrade` 头。

**Q：上传大文件失败？**
A：默认 500MB，且反向代理（Nginx `client_max_body_size`）也要放宽。

**Q：注册提示 IP 达到上限？**
A：换网络、让管理员在后台调整上限，或在登录页提交多开申请；服务器本机不受限。

**Q：忘记管理员密码？**
A：停止服务，设置 `ADMIN_PASSWORD=新密码`、`TCHAT_ADMIN_FORCE=1`，启动一次后去掉 `TCHAT_ADMIN_FORCE`。

**Q：从 1.2 升级后数据在哪？**
A：在 `data/users/users.db`、`data/messages/messages.db`、`data/files/`；旧 `chatroom.db` 保留作备份。

**Q：怎么完全重置？**
A：停止服务，备份后删除整个 `data/`，再启动；会重新生成管理员和空数据库。

## 九、安全建议

1. 首次登录立即修改管理员密码。
2. 公网部署使用 HTTPS 和反向代理，不要直接暴露 5000 端口。
3. 定期备份 `data/`。
4. 不要把 `data/`、`.venv/`、`chatroom.db` 上传到公开仓库。
5. 如果多人共用出口 IP，适当调大 IP 注册上限或使用多开申请。
